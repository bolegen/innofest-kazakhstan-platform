# INNOFEST Kazakhstan — версия для Netlify и Supabase

Платформа содержит регистрацию и вход по email/паролю, кабинет участника, подачу проекта с файлом, анализ сходства, экспертный чек-лист, админ-панель, закрытый архив и импорт заявок из Google Sheets.

## Что уже настроено

- Клиент подключён к Supabase-проекту `kchyhevlgkikhopfbjyh` через URL и publishable key в `.env.production`. Это публичные параметры, допустимые в браузере.
- В `supabase/schema.sql` находятся таблицы, роли, правила Row Level Security и приватное хранилище файлов.
- В `supabase/seed.sql` — 25 архивных записей с публичными источниками за 2021, 2022, 2023 и 2025 годы. Годы 2020, 2024 и 2026 оставлены пустыми: подтверждённые записи не найдены.
- Серверные функции Netlify выполняют сравнение заявок и импорт Google Sheets. Ключи с расширенными правами остаются только на сервере.

## 1. Подготовка Supabase

1. Откройте **Supabase → SQL Editor** в проекте `kchyhevlgkikhopfbjyh`.
2. Выполните весь файл `supabase/schema.sql`, затем `supabase/seed.sql`.
3. В **Authentication → Providers → Email** включите вход по email/паролю. Настройте подтверждение почты по желанию. В **Authentication → URL Configuration** добавьте домен будущего сайта Netlify в Site URL и Redirect URLs. Для локальной разработки добавьте `http://localhost:5173/**`.
4. Зарегистрируйте свой аккаунт на сайте. Затем в SQL Editor выполните команду из конца `supabase/schema.sql`, заменив `YOUR_EMAIL@example.com` на свой email. Это единственный шаг первоначального назначения администратора.

**Важно:** на момент подготовки проекта таблица `archive_projects` по указанному URL Supabase возвращала HTTP 404. Это значит, что SQL-схема ещё не применена; до шага 2 выше сайт не сможет сохранять заявки.

## 2. Публикация на Netlify

Загрузите **исходники проекта** в Git-репозиторий и подключите его в Netlify. Настройки сборки уже указаны в `netlify.toml`: `npm run build`, каталог публикации `dist`, функции `netlify/functions`. Простая загрузка папки `dist` не разворачивает серверные функции.

В **Site configuration → Environment variables** задайте серверные секреты. Публичные `VITE_` уже находятся в `.env.production`; при необходимости их можно переопределить в Netlify.

| Имя | Значение | Где используется |
| --- | --- | --- |
| `VITE_SUPABASE_URL` | `https://kchyhevlgkikhopfbjyh.supabase.co` | клиент |
| `VITE_SUPABASE_ANON_KEY` | выданный publishable key `sb_publishable_…` | клиент |
| `SUPABASE_URL` | тот же URL | функции |
| `SUPABASE_SERVICE_ROLE_KEY` | service role key из Supabase → Project Settings → API | функции, только секрет Netlify |
| `ALEM_GPT_OSS_API_KEY` | API key сервиса GPT OSS в Alem Plus | анализ заявок, только секрет Netlify |

После изменения переменных перезапустите deploy. **Никогда не задавайте `SUPABASE_SERVICE_ROLE_KEY` или `ALEM_GPT_OSS_API_KEY` с префиксом `VITE_`: Vite встроит такие значения в публичный JavaScript.**

## 3. Локальная разработка

```bash
npm install
cp .env.example .env.local
npm run dev
```

Заполните публичные переменные `VITE_` в `.env.local`. Для проверки серверных функций локально используйте Netlify CLI с секретами в среде запуска. Файл `.env.local` исключён из пакета и Git.

## Как работает анализ

1. При подаче заявки сайт извлекает текст из PDF, DOCX, TXT или MD (до 8 МБ), сохраняет файл в приватный Supabase Storage и заявку в базе.
2. Функция `analyze` проверяет сессию пользователя и сопоставляет заявку с архивом. Базовый слой вычисляет сходство названий и пересечение ключевых слов концепции.
3. При наличии `ALEM_GPT_OSS_API_KEY` функция передаёт новой заявке и архивным кандидатам одну модель GPT OSS (`gpt-oss`) в Alem Plus. Модель оценивает сходство по проблеме, аудитории, решению и отличиям и возвращает обоснование. Если API недоступен, результат явно помечается как текстовое сравнение.
4. Пользователь видит пять ближайших архивных записей, проценты и ссылки на источники. Это предварительная подсказка; эксперт принимает решение по чек-листу, администратор управляет статусом.

Модель **не обучается** на архиве в смысле изменения весов. При каждом анализе она получает актуальные записи архива для поиска сходства. Пустые годы и краткие описания ограничивают полноту проверки. Сервис не заявляет, что «такого проекта никогда не было».

## Google Sheets

Администратор вставляет ссылку на таблицу с доступом для чтения. Функция импортирует до 500 строк с колонками «Название» и «Описание» (поддерживаются также некоторые русские, казахские и английские варианты заголовков), затем по кнопке анализирует ожидающие заявки. Повторный импорт той же таблицы не создаёт дубликаты по номеру строки. Если исходные строки меняются, следует проверить результат вручную: ключ привязан к позиции строки.

## Проверка после развертывания

1. Регистрация нового участника и вход по паролю.
2. Подача заявки с файлом и просмотр результата в «Мои заявки».
3. Назначение эксперта по ID в админ-панели; вход эксперта и сохранение чек-листа.
4. Проверка, что обычный участник не видит разделы «Админ-панель» и «Архив» и не может прочитать их записи через API Supabase.

Исходный код можно изменить под официальный регламент фестиваля и дополнить архив документами организаторов.
